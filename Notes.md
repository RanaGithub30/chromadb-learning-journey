# ChromaDB Notes

## 1. ChromaDB

ChromaDB is an open-source vector database used to store documents, metadata,
and vector embeddings. It supports semantic search, so similar meanings can be
found even when the exact words are different.

Common use cases include:

- Retrieval-Augmented Generation (RAG)
- Semantic search
- Chatbots and recommendation systems
- AI applications that need relevant context from stored documents

## 2. Embeddings

An embedding is a numerical vector that represents the meaning of text. ChromaDB
can generate embeddings automatically when documents are added to a collection.
During a query, the query text is converted into an embedding and compared with
the stored embeddings.

## 3. Chroma Client

A Chroma client is the main interface used to connect to ChromaDB and manage
collections and documents.

```python
import chromadb

client = chromadb.Client()
```

`chromadb.Client()` is suitable for an in-memory Ephemeral client. Data may be
lost when the process or application is restarted.

## 4. Persistent Client

`PersistentClient` stores data on disk at the specified path.

```python
client = chromadb.PersistentClient(path="./chroma_db")
```

The project stores local data in the `chroma_db/` folder. That data remains
available after restarting Python or the application.

## 5. Cloud Client

`CloudClient` connects the application to a Chroma Cloud database.

```python
client = chromadb.CloudClient(
    api_key="CHROMA_API_KEY",
    tenant="CHROMA_TENANT",
    database="CHROMA_DATABASE",
)
```

API credentials should be kept in an environment file rather than committed to
source control. The project loads them through `python-dotenv`.

## 6. Collections

A collection is a named group of documents and their embeddings. It is similar
to a table in a relational database.

```python
collection = client.get_or_create_collection(name="vehicles")
```

`get_or_create_collection()` creates the collection when it does not exist and
reuses it when it already exists.

## 7. Adding and Updating Documents

Each document must have a unique ID.

```python
collection.upsert(
    ids=["car", "bike", "boat"],
    documents=[
        "car runs on road",
        "bike runs on road",
        "boat runs on water",
    ],
)
```

- `add()` inserts documents.
- `upsert()` inserts new documents or updates existing IDs.
- `update()` updates existing documents or metadata.
- `delete()` removes documents.

Using unique, consistent IDs helps prevent duplicate records.

## 8. Querying a Collection

ChromaDB can find the documents most similar to a query.

```python
results = collection.query(
    query_texts=["Which vehicle travels on water?"],
    n_results=2,
)
```

`n_results` controls how many matching records are returned. The result contains
document IDs, documents, metadata, distances, and other available data.

Smaller distance values generally indicate a closer semantic match, but the
exact interpretation can depend on the selected embedding and distance metric.

## 9. Getting Stored Data

Use `get()` to retrieve records directly or filter a collection.

```python
data = collection.get()
print(data)
```

## 10. Project Examples

- `main.py` demonstrates Chroma Cloud, `upsert()`, and semantic querying.
- `createCollection.py` demonstrates a persistent local collection.
- `query.py` demonstrates in-memory storage and querying.
- `chroma_db/` contains local persistent ChromaDB files generated by the project.

## 11. Basic Workflow

1. Connect with `Client`, `PersistentClient`, or `CloudClient`.
2. Create or reuse a collection.
3. Add or upsert documents with unique IDs.
4. Query the collection with natural-language text.
5. Use the closest returned documents as context for an application or RAG prompt.
